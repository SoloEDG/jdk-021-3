# 午市厨房

需要 Node.js 22 或更新版本。

```sh
npm install
npm run dev
```

类型检查及生产构建：

```sh
npm run typecheck
npm run build
```

Docker 启动：

```sh
docker compose up --build
```

打开 http://localhost:18221 。

## 玩法：预约宴席

开餐前先接三桌宴席，再用同一批库存和灶台同时应付散客：

- **开餐前定桌**：为每桌指定到店时间、菜品（最多 3 道）和整桌报价。到店时间只能在可约窗口内滑动，且必须留出足够时间让固定耐心在打烊前走完；一旦开餐，时间、菜单、报价全部锁定。
- **提前到店**：每桌都有固定的「可能提前量」，会在约定时间前突然出现并开始计耐心。耐心是合同条款，不能靠拖时间来换空间；三桌的到店时间交错，逼你在中途同时应付两张桌。
- **整桌共享耐心，齐菜才能交付**：桌单在客人入席后才开始倒计时，所有菜全部装盘后进入「待确认」，一次交付整桌。任何一道没装盘都不能拆开上菜，也不能把宴席菜当作散客订单结账。
- **独立失温**：每道菜仍然起锅 15 秒后开始失温。齐菜后展示整桌平均品质、最冷的一道菜及其扣分，再由你决定整桌交付、拒绝整桌（按违约条款赔钱）或退回重做其中某一道。
- **报废与重做**：装盘前丢弃会把这格标为报废，桌单保留，重新备料即可；已装盘的菜可以退回重做，同样记一次报废成本，桌单状态不丢。
- **食材预留**：可以为某桌预留原料，保证成席。预留不消耗库存，但会立刻从「可用」里扣掉，散客备料只能动用剩下的现货。解除预留只归还尚未使用的部分，已经备料、下锅或报废的原料不会退回。
- **采购有在途时间**：补货下单后要等 8 秒到货，付款立刻入账。所以「先抢现货再临时补货」会付出时间代价，预留仍然是保住宴席的主要手段。
- **违约**：超时未齐菜、整桌拒绝、打烊仍未交付都会按报价比例记违约损失，每桌只记一次。

三桌的初始到店时间为 44s / 76s / 104s，且都可能提前 8–12 秒出现，散客 0 秒起就会陆续进门抢同一批库存。
